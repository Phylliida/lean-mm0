# Stock-MM0 coverage of the example suite

Generated by `coverage_worker.py` over every `examples/*.lean`, one
subprocess per file (fresh bridge/db_cert globals).  Each file is run
through the **real** pipeline (`src.lean_parser.elaborate` = parser ->
elaborator -> kernel); every elaborated decl whose type is `Eq Nat lhs rhs`
over closed Nat is a *de-refl obligation*, which the bridge certifies and
**stock mm0-c** checks.  Numbers below are extracted from the sweep output
by script, not hand-transcribed.

## Headline

- **59 example files** swept (deterministic: two runs identical).
- **40 elaborate** in this standalone harness; **19 do not** 
  -- a *harness/stdlib limitation*, not a bridge one (see below).
- Of the 40 elaborated: **114 de-refl obligations**, of which
  **42 certify through stock mm0-c (37%)**, 72 skip.
- **10 files fully certified** (every obligation), 11 partially, 13 with obligations but none yet, 6 with no closed-Nat obligations.
- **Invariant (machine-checked): every file with >=1 certified obligation
  passes BOTH mm0-rs and mm0-c (rc=0).**  Result: OK.

## Honest scope

The bridge certifies *closed-Nat de-refl obligations* -- the `Eq Nat a b`
goals that hold by computation (`by rfl` / `Eq.refl`).  It does **not** yet
cover: proofs with free variables (induction steps, abstract lemmas --
the `nf-mismatch`/`nonclosed` skips), obligations over other types than
`Eq Nat` (counted as non-obligations), or the 19 files that need a fuller
stdlib to elaborate.  What it *does* show: across the elaborating suite,
**42 of 114** real computational obligations are discharged
end-to-end by the 815-line C kernel, every one faithfulness-guarded
against `src/kernel.py`'s own whnf.
